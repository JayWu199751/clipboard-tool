- **开机启动后任务栏挂着一个「点了没反应」的面板按钮（2026-09-19）**：用户报「开机启动后任务栏（不是托盘）有剪切板图标在运行，点击后无响应」，要求自启时别出现它。**根因不在开机启动，也不在配置**——`tauri.conf.json` 里 `skipTaskbar` 一直是 `true`。读 tao 0.35.3 源码得到机制：`skip_taskbar` 的实现是**建窗那一刻**调一次 `ITaskbarList::DeleteTab`（`platform_impl/windows/window.rs:1334` → `:1529`），而面板以 `visible:false` 创建，那一刻任务栏上根本没有按钮可删，该调用是空操作；真正让它显形的是 `setup` 里 ready-to-show 热身的 `win.show()`，外壳在窗口**变可见**那一刻自己补上按钮，此后 `set_visible` 只碰 `VISIBLE` 位、不再管任务栏（`window.rs:164`）。叠加本应用的「关闭」= [停靠](../CONTEXT.md)到屏外、窗口始终可见（`park_offscreen` 只改位置，从不 hide），按钮就挂满整个会话，点它只是把一个屏幕外的窗口切到前台 = 看着像没反应。**所以任何一次启动都会中，不只自启**；自启只是最容易撞见的场景——登录后没人呼出面板，按钮一直空挂着，手动启动的人下一秒就把面板叫出来了，注意力不在任务栏。**修法落在唯一的一次「不可见→可见」转换**：`PanelWindow::show()` 里 `ShowWindow` **之前**给 `GWL_EXSTYLE` 补 `WS_EX_TOOLWINDOW`（读改写，`WS_EX_TRANSPARENT` 那套同先例）。没选社区常见的「show() 之后再 `set_skip_taskbar(true)`」：那是一次性 `DeleteTab` 去追外壳的补按钮，跨进程消息谁后手谁赢，而且此后任何一次可见性重评估还会再补回来；`WS_EX_TOOLWINDOW` 由外壳在**评估阶段**排除，与时机无关。样式在窗口尚不可见时改，也不必 hide/show 一轮强迫外壳重算（WPF 改 `ShowInTaskbar` 要重建句柄，正是因为它在可见状态下改）。**顺带收益**：面板同时从 `Alt+Tab` 消失——原先它能被 Alt+Tab 切进去、切到的又是屏外窗口，那是同一问题的另一半。**唯一风险面是取焦点**：工具窗口照样可前台、可 `SetFocus`，且全仓没有一处按 `GWL_EXSTYLE` 或可见性筛窗口（`focus_paste` / `source_app` / `click_watcher` grep 为零），故搜索 / 备注 / 捕获三态理论不受影响——只能真机验，已进 README「待真机验证」。`alwaysOnTop`（`SetWindowPos(HWND_TOPMOST)`）与圆角穿透同不受影响。判据：node 38 + cargo 93 = 131 例、`npx tsc --noEmit` 零输出、`cargo check --all-targets` 零警告。本轮**没有新增单测**——改的是纯效果（一次窗口样式写入），无判定可提，按红线它归 `panel_window.rs`（该 module 本就是几何 / 焦点 / 穿透的唯一归属，文件头职责行加上「上不上任务栏」）。同步：README「托盘菜单」段后新增一段（图标只在托盘 + 为什么）、「故障排查」一行（现象 → 先查那次样式）、「待真机验证」首条；architecture 的 `panel_window.rs` 行（职责与 `show` 的说明）；pitfalls 第 3 节一条（`skipTaskbar` 为何管不住「以移到屏外代替隐藏」的浮层，含为什么不补 `DeleteTab`）。无 ADR：一次 `|=` 上样式位，回退成本就是删掉那三行。行数：`panel_window.rs` 331 → 345、`main.rs` 864 → 865（热身分一句指路）。**【本条的结论与修法已被同日第二轮真机读数证伪——样式位在 `show()` 之前挂会被 tao 整体重写抹掉，见上一条。】**
