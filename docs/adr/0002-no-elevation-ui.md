# 渲染层不做任何提权提示

既然 ADR-0001 保证进程常驻高完整性，工具就不存在「未提权」这个用户可见状态，因此**界面上一律不提提权**：没有横幅、没有呼出时提醒、没有「以管理员身份重启」、`settings.json` 里也没有提权字段。提权事实只写 `stderr` 与 `diag.log`，供开发者排查。

这条在 2026-08-23 的访谈里推翻了自己前一版的定稿：当时设计过一整套「呼出时检测前台是管理员窗口 → 弹层一次 → 常驻横幅 + 一键提权」的状态机，并规定提权状态绝不持久化（只记会话内实测的助手连接状态）。终版把这套 UI 连同提权助手进程一起退役，因为常驻提权让它没有存在的前提。

## Consequences

- 未来看到「管理员窗口热键失效」的报障，先确认跑的是不是提权产物，而不是去加提示条——那正是本 ADR 否决过的方案。
- 清单被改写（`CLIPBOARD_TOOL_ELEVATED=0`）导致未提权时，工具静默降级，不报错。这是刻意的：release 清单已保证提权，走到那一支说明是人为改动。
